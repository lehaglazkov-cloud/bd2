🚨 Етап 1: Аналіз джерел загроз

⚠️ Повідомлення системи: Головну базу даних заблоковано. У логах зафіксовано несанкціоноване втручання та пошкодження записів.

📖 Ключ етапу: Джерела загроз бувають природними, технічними та людськими. Статистика показує, що помилкові чи навмисні дії людей становлять найбільшу частку (50-80%) порушень безпеки.

🗄️ Симуляція таблиці інцидентів (`sys_audit`):

Log_IDEventOrigin_Source
301Unauthorized Data ModificationHuman Error / Operator Action

🔒 Етап 2: Порушення властивостей інформації

⚠️ Повідомлення системи: Зловмисник отримав повний адміністративний доступ до керування інформаційною системою.

📖 Ключ етапу: Інформаційна безпека базується на захисті трьох ключових властивостей: конфіденційність, цілісність та доступність. Отримання повного контролю над системою та зміна прав користувачів безпосередньо загрожують цим аспектам.

🗄️ Симуляція прав доступу (`access_control`):

UserRole AssignedSecurity Status
Guest_ExternalFull System AdministratorCOMPROMISED

Баг у системі: Який принцип безпеки порушено при отриманні повного керування системою сторонньою особою?

🐛 Етап 3: Мережеві черв'яки (Worms)

⚠️ Повідомлення системи: У внутрішній мережі зафіксовано лавиноподібне самокопіювання коду через уразливості в операційній системі без участі користувачів.

📖 Ключ етапу: *Мережеві хробаки* — різновид шкідливих програм, які проникають на комп'ютер без участі користувача, використовуючи вразливості («дірки») в ПО та автоматично розмножуючись мережами.

🗄️ Симуляція моніторингу трафіку (`net_worms`):

Packet_IDPropagation_MethodUser_Interaction
778Exploiting OS VulnerabilitiesNone (Autonomous replication)

Баг у системі: Класифікуйте загрозу та оберіть правильну дію для локалізації:

🐎 Етап 4: Троянські програми (Trojan Horse)

⚠️ Повідомлення системи: Під виглядом корисної утиліти на сервер встановлено прихований компонент, який передає паролі на зовнішній сервер, не створюючи власних копій.

📖 Ключ етапу: *Троянський кінь* — шкідлива програма для несанкціонованого доступу, яка не має механізму створення власних копій (на відміну від вірусів), а маскується під корисне ПЗ.

🗄️ Симуляція процесів (`app_manager`):

App_NameFunctionSelf-Replication
Free_Optimizer.exeHidden Backdoor / Password GrabberDisabled (No copies)

Баг у системі: Визначте тип шкідливого ПЗ і правильний спосіб захисту:

🎣 Етап 5: Фішинг та підроблені сайти

⚠️ Повідомлення системи: Масова розсилка листів від імені адміністрації змусила співробітників ввести корпоративні облікові дані на фішинговому сайті.

📖 Ключ етапу: *Фішинг* — масове розсилання електронних листів і створення фальшивих сайтів із метою викрадення персональних даних, паролів та доступу до ресурсів.

🗄️ Симуляція звернень до шлюзу (`phishing_logs`):

Баг у системі: Оберіть правильну стратегію безпеки проти фішингу:

💣 Етап 6: Логічні та часові бомби

⚠️ Повідомлення системи: У базі даних виявлено прихований програмний код, який має активуватися в конкретну дату й знищити таблиці.

📖 Ключ етапу: *Логічна бомба* (або часова бомба) — програма або закладка, яка спрацьовує при настанні певної умови чи часу, знищуючи або спотворюючи інформаційні ресурси.

🗄️ Симуляція тригерів БД (`triggers_check`):

TriggerConditionAction
TRG_BOMB_01IF CURRENT_DATE >= '2026-07-01'DROP DATABASE records;

Баг у системі: Як знешкодити логічну бомбу в системі?

🧟 Етап 7: Програми-зомбі та жадібні програми

⚠️ Повідомлення системи: Ресурси сервера вичерпано через фоновий процес, який монополізує процесорний час і таємно залучає систему до атак.

📖 Ключ етапу: *Зомбі* — програми, що приховано підключаються до ПК для запуску атак. *«Жадібні програми»* монополізують системні ресурси, порушуючи доступність інших додатків.

🗄️ Симуляція завантаження CPU (`resource_monitor`):

greedy_daemon.exe99.8%Monopolizing CPU / Remote Botnet Node

🔑 Етап 8: Захоплювачі паролів (Password Grabbers)

⚠️ Повідомлення системи: Виявлено утиліту прихованого адміністрування та кейлоггер, що перехоплюють натискання клавіш користувачів.

📖 Ключ етапу: *Захоплювачі паролів* та *утиліти прихованого адміністрування (backdoor)* призначені для крадіжки облікових даних і несанкціонованого віддаленого контролю за системою без відома користувача.

🗄️ Симуляція перехоплення клавіатури (`key_loggers`):

UtilityTargetStatus
hook_dll.exeKeyboard Buffer / Password InputACTIVE & SNIFFING

Баг у системі: Який комплекс заходів зупинить крадіжку паролів?

🌐 Етап 9: DDoS-атаки (Розподілені атаки на відмову в обслуговуванні)

⚠️ Повідомлення системи: Вхідний шлюз бази даних завалено мільйонами запитів з ботнет-мережі, легітимні користувачі не можуть підключитися.

📖 Ключ етапу: *DDoS-атака* (Denial-of-service) — напад на систему з метою зробити її ресурси недоступними для користувачів, для яких вона призначена (руйнування *доступності*).
